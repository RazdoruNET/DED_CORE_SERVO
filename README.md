# DED CORE SERVO — модуль привода сервопривода для DED CORE V4

Прошивка ESP32 для внешнего привода сервопривода (заслонка, клапан, эксцентрик)
в системе **DED MOTO SYSTEM**. Модуль подключается к точке доступа базового блока
[DED_CORE_V4](https://github.com/RazdoruNET/DED_CORE_V4) как обычный WiFi-клиент,
получает целевое положение сервы в кадре телеметрии WebSocket и отрабатывает его
H-мостом по аналоговому датчику положения.

Это переписанная версия модуля `DED_SERVO_DRIVER` (ядро DED BOX V3). Старая
прошивка не может работать с V4: пароль точки доступа ядра больше не зашит в
исходники, а шкала положения сервы сменилась с 0…100 на 0…255.

## Что изменилось относительно DED_SERVO_DRIVER

| | DED_SERVO_DRIVER (V3) | DED CORE SERVO (V4) |
|---|---|---|
| Ядро | `DED_BOX_V3` с паролем из прошивки | `DED_BOX_V4`, пароль уникален для блока |
| Подключение | пароль вшит в `PROPS.h` | сопряжение из приложения блока (`DED_PAIR_*`) |
| Шкала `servo_position` | 0…100 | 0…255 (как в карте и настройках V4) |
| Потеря связи с ядром | привод оставался с прежней командой | привод фиксируется тормозом |
| Ошибка привода (заклинивание) | остановка до перезагрузки | 3 попытки, затем остановка до новой уставки; кадр `servo_error` ядру |
| Bootloop | счётчик в NVS не работал (ключ длиннее 15 символов) | счётчик неудачных стартов, после 3 — портал настройки |
| Структура | Arduino-скетч, всё в `.h` | PlatformIO: `src/config`, `src/app`, `src/net` |
| Отладка | `Serial.print` в 1 мс цикле | лог только по событиям, контур в отдельной задаче |

## Железо

| Сигнал | GPIO | Примечание |
|---|---|---|
| H-мост «вверх» | 16 | HIGH = движение |
| H-мост «вниз» | 17 | HIGH = движение |
| Разрешение драйвера | 32 | HIGH = драйвер включён |
| Датчик положения | 35 | аналоговый вход, ADC1, 0…3,3 В |
| Резерв | 34 | вход, в контуре не участвует |

Тормоз — оба вывода моста в HIGH (двигатель замкнут), выбег — оба в LOW.
Подробности и требования к питанию — [docs/HARDWARE.md](docs/HARDWARE.md).

## Сборка и прошивка

```bash
pio run            # сборка
pio run -t upload  # прошивка по USB
pio device monitor # лог, 115200
```

Версия платформы (`espressif32@7.0.1`, Arduino core 2.0.17) закреплена так же,
как в DED_CORE_V4: на Arduino core 3.x не собираются WebSockets 2.4 и
ESPAsyncWebServer 1.2.

## Первое подключение

1. Включите блок питания. Модуль без настроек поднимает портал `DED_SERVO_DRIVER`
   и начинает искать сеть сопряжения ядра.
2. В приложении DED CORE V4 откройте «Настройки» → «Модули» и нажмите «Найти модуль».
   Блок на 90 секунд поднимает открытую сеть `DED_PAIR_XXXX` с маршрутом
   `GET /module/pair`. Кнопок на блоке нет — корпус закрыт, окно открывает только
   приложение с ключом устройства. Телефон на время окна отключится от блока.
3. Модуль находит эту сеть, получает имя и пароль основной точки доступа ядра,
   сохраняет их в NVS и перезагружается.
4. Дальше модуль подключается к `DED_BOX_V4` и к WebSocket ядра на порту 81.

Сопряжение повторяют, если на блоке сменили пароль точки доступа или заменили
ядро. Пока линка нет, модуль пробует сопряжение каждые 20 секунд (первые 60 секунд
после потери связи — ждёт, вдруг это кратковременный сбой).

Ручной вариант — портал: подключитесь к `DED_SERVO_DRIVER` и откройте
`http://192.168.4.1/`, впишите имя и пароль точки доступа ядра. Пароль,
сохранённый ранее, в страницу не выводится: пустое поле означает «не менять».

## Портал настройки

Портал открывается, когда модуль не настроен, после трёх неудачных стартов или
после потери связи. Точка доступа `DED_SERVO_DRIVER` открытая, страница — на
`http://192.168.4.1/`. На странице: состояние линка, уставка и положение привода,
ошибка, ручной ввод параметров ядра, кнопка поиска ядра, сброс ошибки и обновление
прошивки.

Обновление прошивки закрыто паролем: он создаётся при первом старте и печатается
в лог один раз (`SETTINGS: пароль обновления прошивки: …`). Логин — `admin`.

## Поведение привода

* Уставка приходит из кадра ядра: `servo_position` 0…255 → 0…4095 ADC.
* `servo: false` в кадре — уставка 0 (привод возвращается в исходное положение).
* Нет кадров дольше 3 секунд — привод на тормозе, ошибки нет. Команда «стоп» без
  команды ядра не выполняется: привод не поедет сам.
* Заклинивание: если за 25 измерений привод прошёл меньше 25 отсчётов, попытка
  повторяется через 1,5 секунды; после трёх неудач привод остаётся на тормозе до
  новой уставки (сдвиг больше 200 отсчётов) или ручного сброса.
* Ошибка уходит ядру кадром `servo_error` (см. [docs/PROTOCOL.md](docs/PROTOCOL.md)).
